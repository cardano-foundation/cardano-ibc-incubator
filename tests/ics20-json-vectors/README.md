# ICS-20 Classic JSON vectors

These fixtures pin the exact packet bytes produced by the supported Classic
ICS-20 implementations:

- Cardano's existing sorted JavaScript JSON encoding
- ibc-go v8.7.0 sorted JSON encoding
- ibc-go v10.2.0 struct-ordered JSON encoding
- ibc-rs v0.53.0 struct-ordered `serde-json-wasm` encoding

The cases cover omitted memos, ordinary memos, JSON string escapes, UTF-8,
Go's HTML escaping, Go's escaping of Unicode line separators, and ibc-rs's
explicit empty memo and uppercase long control escapes. The two Go profiles
are generated by calling `FungibleTokenPacketData.GetBytes()` in the repository
modules that pin those ibc-go versions. The ibc-rs
[`send_transfer`](https://github.com/informalsystems/ibc-rs/blob/v0.53.0/ibc-apps/ics20-transfer/src/handler/send_transfer.rs)
path serializes `PacketData` with the workspace's `serde_json` alias, which is
`serde-json-wasm` 1.0.1. The profile pins the
[`dummy_json_packet_data`](https://github.com/informalsystems/ibc-rs/blob/v0.53.0/ibc-apps/ics20-transfer/types/src/packet.rs)
fixture from v0.53.0. The generated Aiken tests then exercise the exact
resulting bytes on-chain.

The generated file contains the upstream positive vectors. Malformed,
non-canonical, oversized, and invalid UTF-8 cases are kept in the adjacent
hand-authored `fungible_token_packet_data.test.ak` suite.

The fixtures also pin the 512-byte packet ceiling. One case reaches exactly
512 bytes in all three profiles. A second, densely escaped case reaches exactly
512 bytes in both ibc-go profiles while remaining shorter in Cardano's encoding.
The generator rejects any case that exceeds the ceiling and verifies those
boundary lengths during regeneration.

Regenerate and verify the checked-in files with:

```sh
node tests/ics20-json-vectors/generate.mjs --write
node tests/ics20-json-vectors/generate.mjs --check
```

The generator deliberately uses Go 1.25.13, matching CI and the pinned Go
modules.
