The live rehearsal rebuilds the pinned native Injective application with the current Cardano module. A small integration driver calls the pinned Hermes library's production chain endpoints, simulation, signing, broadcast, polling event collector and client watcher. It does not run the release CLI's supervisor. Transactions go through CometBFT RPC. Gateway's real `QueryService` builds initialization messages and observation headers behind a local gRPC server. The server replaces the external Cardano history, block-body and node-context providers with signed fixtures. It uses a local Mithril test network.

Unlike the socket ABCI replay, this application has an unmodified CometBFT clock. The [local parameter profile](readiness-profile.json) uses captured Injective gas and transaction limits and a 48-hour source trust period. The synthetic Cardano network has one-second slots, 20,000-slot epochs and an active-slot coefficient of `1/2`. Its thirteen-row stake tables keep the integration run manageable. Forty retained counters from retired pools and later operational-certificate renewals make recovery require more than one committed continuation. These source parameters are test inputs and are not approved production parameters.

The run starts without Cardano clients in genesis. Hermes creates a certified client and resumes its import after a node restart. It activates a proof root, maintains an idle checkpoint and ingests a certificate for the next epoch. It receives packets and exports and imports the current snapshot format while preserving consensus metadata. A later uncertified proposal remains pending. The watcher must reconstruct historical destination context, request an independently built alternative from its witness Gateway and sign a challenge that commits a freeze. Frozen proofs and unauthorized recovery must fail. Governance then authorizes recovery. A committed continuation must survive restart before recovery completes. Discarded-generation proofs must fail. Further certificates, updates and packets must work after another restart.

Prepare and run from a fresh directory shared with Docker. Docker, Go, Rust and Node must be available. The script builds missing native dependency images, installs the pinned JavaScript dependencies and builds the Gateway preparer and Hermes driver. `READINESS_CARGO_TARGET_DIR` can reuse an existing Cargo cache.

```sh
READINESS_CARGO_TARGET_DIR="$HOME/cardano-hermes-build" \
  bash tests/injective-probabilistic-lifecycle/prepare_readiness.sh \
  "$HOME/injective-live-readiness"
```

The output keeps the exact native export, committed transactions, source fixtures, Gateway requests and Hermes events. `run_readiness.py --resume` accepts the same image and helper arguments to continue an interrupted run. It reads committed state and retained stage results. A successful local rehearsal records `live_rehearsal_complete`. It leaves `production_gate_closed` false. Natural expiry of an uncertified allocation after six hours of credited host progress is not part of this short run. Neither is admission of these source transactions on a real Cardano ledger or a binary upgrade between different Injective application versions. Deployment certification still needs the actual release candidate and approved parameters with the real source services and production Mithril anchor.

The [retained run from 16 October 2026](evidence/live-readiness-20261016/results.json) completed 504 successful committed transactions and one expected unauthorized recovery rejection. The watcher froze the client with 21,542 seconds left on the proposal deadline. Recovery committed checks for 32 of 51 counters before restart and then finished. The largest signed transaction was 6,423 bytes. Peak execution was 4,253,457 gas and the largest successful gas allowance was 7,647,204. These are measurements of this fixture rather than maximum supported workload certification. Compressed transaction records, source data, events and recovery continuations accompany the report.
