# IBC state commitment fixtures

`nextSequenceRecv/ports/{port}/channels/{channel}` commits a CBOR unsigned integer. For sequence `1` the Cardano leaf value is `01`. ibc-go expects the same number as eight big-endian bytes, `0000000000000001`. Light clients compare the decoded numbers and use the original CBOR bytes when verifying the root.

`next-sequence-recv.json` pins this encoding from zero through `uint64` maximum, including a value above JavaScript's safe integer range. Its `version` identifies the fixture format. The roots and proof path come from the Gateway's shared tree implementation. TypeScript tests rebuild and update that tree, and Go tests verify the same proofs in each Cardano light client.

`proofs.json` contains a populated tree with a Tendermint client, consensus states at `1-100` and `2-100`, a connection, a channel and a receive sequence. It also proves absence at `3-100`. Consensus keys retain both revision and height. Gateway tests regenerate the exact CBOR values, roots and proof paths using its shared runtime package. They also check its emitted protobuf bytes against the fixture. Aiken checks those same roots and the native client serialization. The shared Go core checks the paths. Both probabilistic adapters exercise their public `VerifyMembership` and `VerifyNonMembership` methods against these stored roots with protobuf and legacy JSON proofs.

The current client commitment has nine fields. All proof settings and upgrade path segments must match the expected protobuf value. The two deprecated allow-update flags are absent from this codec and therefore mean `false`. A proof cannot establish either flag as `true`. This completes comparison of the current format without changing its committed bytes or introducing a new codec version. Codec activation and broader historical format support remain tracked in #614.

The sparse proof format uses exactly one proof with 64 inner operations. Absence uses an empty leaf witness at the requested key, rather than neighboring leaves from a sorted tree. Malformed constructors, missing operations, unsupported explicit inner hashes and extra proof entries return errors. Older compact proofs may omit the hash field. The leaf hash is fixed by Cardano's commitment scheme rather than the optional ICS-23 leaf metadata.

To regenerate after building the runtime package and installing Gateway dependencies, run `node tests/ibc-state-commitment/generate.mjs --write`. Use `--check` to verify the checked-in JSON and Aiken fixtures. Gateway's ordinary test command performs this check too. A focused Aiken run is `aiken check -m gateway_and_go` from `cardano/onchain`.
