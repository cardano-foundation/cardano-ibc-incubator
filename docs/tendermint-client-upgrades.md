If `chain-0` upgrades to `chain-1` and restarts its height at 1, its existing client on Cardano needs an authenticated transition before it can accept the new headers. Both Aiken client deployments support this through the Gateway's `Msg/UpgradeClient` endpoint. The message returns an unsigned Cardano transaction for the submitter to sign and submit.

The old client must be active and have a nonempty `upgrade_path`. The transaction proves the upgraded Tendermint client and consensus states against the old client's latest consensus root. It uses the old proof specifications and the old upgrade path with `/<old revision height>/upgradedClient` or `/upgradedConsState` appended to the last path segment. The committed values are protobuf `Any` messages. The client value has its custom fields zeroed as in ibc-go v8.7.0.

The replacement adopts the proved chain ID, height, unbonding period, proof specifications and upgrade path. The height must advance when compared as a revision and height pair. The client keeps its trust level, trusting period and maximum clock drift. A shorter unbonding period is rejected if it no longer exceeds the retained trusting period. Proof specifications remain limited to the supported Cosmos SDK IAVL and Tendermint stack. An upgrade cannot introduce another proof algorithm or replace validator code.

The client identity is preserved and the old checkpoint is archived. HostState commits the new client and consensus state in the same transaction. The replacement consensus state uses the proved timestamp and next validator hash with `sentinel_root` as its application root. Membership and nonmembership verification explicitly reject that root. A subsequent authenticated header must establish an application root before packets can use the new revision. Expired or frozen clients cannot use this path.

This change requires a fresh deployment. The Tendermint datum gains a ninth field for `upgrade_path`. The recovery support script also pins the proof verifier's policy. Existing datums, script hashes and height-only public trees cannot be reused. Deploy the matching Gateway, runtime and Cosmos v8 or v10 adapter together. This implements upgrades of Tendermint clients hosted on Cardano. It does not implement upgrades of the Cardano probabilistic client hosted on Cosmos.
