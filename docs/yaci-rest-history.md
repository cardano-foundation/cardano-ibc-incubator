# Yaci REST history

Gateway reads Cardano history through Yaci Store's native REST API. It does not connect to Yaci PostgreSQL or copy Yaci's chain tables into its own database. There is no history import worker. Gateway's existing PostgreSQL holds application state and derived caches. Its existing SQLite consensus indexes hold client proof state.

| Gateway read | Native Yaci REST endpoint |
| --- | --- |
| Latest block and block by height | `/api/v1/blocks/latest` and `/api/v1/blocks/{height}` |
| Blocks in an epoch | `/api/v1/blocks/epoch/{epoch}` |
| Transaction location | `/api/v1/txs/{hash}` |
| Original transaction bodies, witnesses and validity | `/api/v1/blocks/{hash}/cbor` for the transaction's block |
| Historical NFT outputs | `/api/v1/assets/{unit}/transactions` |
| Tokens minted under a deployment policy | `/api/v1/assets/policy/{policy}/history` |
| Historical spends including burns with no replacement NFT | `/api/v1/addresses/{address}/transactions` |
| Pool registration candidates when no external provider is configured | `/api/v1/pools/registrations` with certificates checked in raw blocks |

Historical proofs combine these indexed REST queries on demand. Asset history discovers producing transactions. Address history includes consuming transactions so a burn or cancellation cannot leave a spent NFT appearing live. Gateway checks transaction bodies against their raw block and excludes failed script transactions using the block's validity list. It reconstructs the requested tree and requires its root to match the HostState commitment. It pins a block before the reads and rechecks that block afterward. A rollback, missing required transaction bytes or a root mismatch fails the request. Native REST does not provide a shared transaction snapshot or prove that paginated indexes are complete. The provider must supply complete retained indexes for the requested history. Requests share raw block decoding only within that request. Raw blocks and Yaci chain tables are not persisted. Existing proof caches retain bridge-specific state. Consensus recovery streams indexed history in ascending block order. Each relevant raw block is decoded once and replayed in canonical transaction order. Completed transactions become durable SQLite checkpoints during the download. A resumed recovery verifies its saved transaction and locates the first ascending index page at that block height with bounded page probes. Replay buffers stay bounded as history grows. Proofs remain unavailable until the pinned tip and live client root are revalidated. Page drift or a changed anchor tells consensus recovery to retry from saved progress. Epoch boundary queries read the final page instead of walking the whole epoch.

These routes were checked against upstream Yaci Store `v2.0.2.1` and `v2.0.3`. The [address controller](https://github.com/bloxbean/yaci-store/blob/v2.0.3/stores-api/utxo-api/src/main/java/com/bloxbean/cardano/yaci/store/api/utxo/controller/AddressController.java) exposes address history. Its [storage reader](https://github.com/bloxbean/yaci-store/blob/v2.0.3/stores/utxo/src/main/java/com/bloxbean/cardano/yaci/store/utxo/storage/impl/UtxoStorageReaderImpl.java) includes spending transactions in address history. Asset history includes producing transactions only. Current unspent-output endpoints alone cannot reconstruct earlier state. The transaction-detail service does not reliably populate its validity field in these releases so Gateway obtains validity from raw blocks.

The provider must expose these native endpoints and retain historical outputs, spends and raw blocks from the deployment's manifest checkpoint. Enable `store.assets.enabled=true` for the policy-history API and its mint and burn index. An existing provider that indexed a deployment with this store disabled must replay from before that deployment to populate the index. Disable spent-output pruning with `store.utxo.pruning-enabled=false`. Enable `store.blocks.save-cbor=true` and `store.cardano.return-block-cbor=true` to supply raw block CBOR. Missing or pruned history cannot be recovered from a current UTxO snapshot. There is no PostgreSQL or Cardano node fallback. Cold proof reconstruction can make many REST requests as bridge history grows. A live hosted-provider recovery run is still needed to assess latency and retention.

Set `YACI_STORE_ENDPOINT` to the native API's base URL. `GATEWAY_DB_*` continues to configure application storage. Manifest export, upgrade and migration witness tools read REST too. The independent Deno consensus recovery tool uses `YACI_STORE_ENDPOINT`, `KUPO_URL` and `OGMIOS_URL`. Existing epoch nonce, stake and Ogmios providers remain in use. Public pool ages come from the existing external registration provider because their creation can predate raw-block retention. A local devnet requires its HTTP epoch provider.

For a standalone Gateway using remotely hosted services set `CARDANO_DOCKER_NETWORK_EXTERNAL=false`. Compose creates the network for outgoing API requests without requiring a local Cardano stack. Configure Gateway's existing application database and the hosted Kupo, Ogmios and epoch-provider endpoints. CF's actual base URL, software version and enabled routes still need confirmation. A Blockfrost-compatible endpoint has different paths and cannot be assumed to serve the native Yaci API.
